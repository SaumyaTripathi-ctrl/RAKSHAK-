# Decisions log

Format: **what** — why — alternatives. Newest at the bottom of each phase.

## Phase 1 — skeleton, infra, record spec

**D-001 Repo location: `C:\Users\HP\Downloads\rakshak-app`, not `...\rakshak`.**
Windows paths are case-insensitive, so `...\rakshak` *is* the existing `...\RAKSHAK` folder holding the
old MedRakshak repo. Emptying it to `git init` was blocked (irreversible deletion), so the new repo lives
beside it and nothing was deleted. The old repo was also copied, history included, to
`...\MedRakshak_reference` (read-only reference). Alternative: delete and re-init in place. Rename the folders
yourself whenever convenient; nothing in this repo depends on its own folder name.

**D-002 Frame is 154 bytes (tag/event) and 164 bytes (hub), not 152.**
Adding the approved `key_epoch` (u16) to the frame header/AAD makes the tag/event frame 154 bytes. Hub
samples need GPS and actuator state so their body is 60 bytes, giving 164. The decoder picks the length from
the (unencrypted) `type` byte.

**D-003 `ts_valid` and `lid` share one `flags` byte.** The body had to stay exactly 50 bytes.
Unsynced timestamps are device-monotonic seconds; a `TIME_SYNC` event record carries the epoch/monotonic
pair so the backend can re-base them (spec §6).

**D-004 Nonce = 8 zero bytes ‖ `seq` as u32 little-endian.** The approved spec left endianness open; LE keeps
every multi-byte field consistent.

**D-005 Event records reuse the 50-byte tag layout** (`event_code`, `arg0`, `arg1` replace the three sensor
fields) so there is one body size to parse/store/transport.

**D-006 Hub forwards tag frames opaquely.** The hub never holds tag keys; it ACKs tag batches by `seq` from the
cleartext header. A compromised hub can drop data (detected as `MISSING`) but cannot forge or edit tag records.

**D-007 Fixed-point integers instead of JSON/floats** in the record format; the JSON records shown in the
product explainer are the *decoded, API-level* view.

**D-008 Vectors are generated by the Python reference, but not only self-checked.** The HKDF is checked against
RFC 5869 Appendix A.1 in both languages, AES-GCM/SHA-256 come from audited libraries (`cryptography`, mbedTLS), and
the C test asserts byte-equality with Python for every body, hash and frame. Stale vectors fail CI.

**D-009 Host C test builds a minimal, pinned mbedTLS 3.6.2** (SHA-256 of the tarball verified in
`run_host_test.sh`) with a hand-written config; locally compiled with `zig cc` (pip `ziglang`) because
Windows has no gcc, in CI with `cc`.

**D-010 Arduino-ESP32 ≥ 3.0 via the `pioarduino` PlatformIO platform.** The official `espressif32` platform is
stuck on Arduino-ESP32 2.x; pioarduino tracks 3.x/IDF 5.x. Alternative: ESP-IDF + arduino-as-component (heavier).

**D-011 Broker & database.** Mosquitto: TLS 1.2+ only, `allow_anonymous false`, per-device users (username = hub
id) and an ACL that restricts a hub to its own `rakshak/{hub_id}/…` topics. Passwords come from env at container
start (dev defaults in `.env.example`). A `certs` one-shot service generates a **dev-only** CA + server cert into a
volume, so `docker compose up` needs no host tooling. Postgres is published on `127.0.0.1:55432` (5432 was already
taken on the dev machine; override with `POSTGRES_HOST_PORT`).

**D-012 No model pickles or Git LFS in the repo.** Models are trained from the simulator by `make train` (and at
image build). Reports/model cards are committed. Avoids LFS for a hackathon repo and keeps the repo reproducible.

**D-013 License: MIT.** Simple, permissive; change if the team wants otherwise.

**D-014 Python 3.11+ supported; developed on 3.12.** CI uses 3.11 (the approved target).
